# RFC 25: Player Pages Have an Id of Their Own

> **Status: built (2026-11-06).** A player's page is `/servers/:id/players/<id>` with an id made by this site; the SteamID64 is no longer in an address that the site writes. The statistics are still kept under the SteamID64.

## 1. Abstract
Player pages used the player's SteamID64 as the last part of their address (`/servers/:id/players/76561198...`), and so did the admin's view log filter (`?player=`). Those addresses are pasted into chats, shared, kept in browser history and sent in referrer headers. A SteamID64 is public on Steam, but a link should not be the place where it is spread. This RFC gives each player an id of this site's own for addresses.

## 2. Design
*   **The id.** 16 lower-case hexadecimal characters from a random source (64 bits), made the first time a player needs one and never changed. Nothing about the player can be worked out from it. It is the same on every server of the site (the SteamID64 is too), kept in the table `player_ids (pid, steam_id UNIQUE, created_at)`.
*   **Where it is used.** The links on the leaderboard, the round page and the player page itself, and the `player` filter of the view log. Bots have one too.
*   **What does not change.** The statistics, the replay data and the bridge keep using the SteamID64, and the player page still shows it as text (it is public on Steam). Only the addresses changed.
*   **Old addresses.** `/servers/:id/players/<SteamID64>` for a player who has played on that server is answered with a `301` to the new address, keeping the query string, so a saved link still works. A SteamID64 that is not a player there is not given an id (it goes to the overview like any unknown player), so nobody can fill the table by asking. The view log accepts either form of `player`.
*   **Making ids.** Migration v28 gives an id to every player already in the round tables. Others get theirs when a page first links to them. The ids are kept in memory after the first lookup.

## 3. Not covered
*   The replay's data (`track.json`) and the pages' text still carry SteamID64s; they are for signed-in users or public on Steam.
*   An id does not hide who a player is from someone who already knows the SteamID64: the old address redirects to the new one. That is the price of keeping saved links working; removing the redirect is a one-line change if it is not wanted.

## 4. Tests
The id has the right shape, is stable and does not contain the SteamID64; the leaderboard, round page and view log link to ids and not to SteamID64s; the old address redirects with its query; an id that was never given out and a stranger's SteamID64 go to the overview and make no row; bots work with ids.
