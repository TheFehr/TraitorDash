# RFC 37: Entities That Are Templates Are Not in the World (the Hovering Diamond Block of `ttt_minecraft_b7_summer`)

> **Status: proposed (2026-11-17), not built.** Asked for by the maintainer after the diamond and gold blocks of `ttt_minecraft_b7_summer` were seen hovering in front of the furnace in the 3D view ("why do the gold and diamond block hover?"). Extends RFC 33 (3 and 9a: what is hidden at round start) and RFC 35 (start states of moving parts). Found by reading the map (2026-11-17).

## 1. Abstract
A Source map can name entities in a `point_template` (`Template01` to `Template16`). The engine **removes the named entities from the world when the map starts** and keeps them only as templates, to spawn copies when the template is triggered (a spawn input from a connection). The extractor does not know this: it draws every brush entity and every placed prop at the position the map file gives. A templated entity therefore appears in our picture although it does not exist at round start.

On `ttt_minecraft_b7_summer` the diamond cube is a `func_physbox` named `DiaBlock`, 40 units above the ground (the highest surface under it is z 256, the cube spans z 296 to 312), and the `point_template` `Furnace_Template` lists `template01 = DiaBlock`. A copy is spawned only when a player feeds the furnace. In our picture it hovers; in the game it is not there. The map has 14 templates; the pattern is general (ammo, chest weapons, brick blocks, clay, ore, the traitor items and so on).

This RFC reads the templates and **leaves out every entity they name** from everything the pipeline draws.

## 2. What the map shows (measured 2026-11-17)

The gold block is the same kind of entity (to be confirmed by the measurement in section 7). Which entity classes are templated on the other maps is measured by the census of section 5.

## 3. How Source treats a template (what is read)
*   `point_template`: the keyvalues `Template01` to `Template16` hold **entity names** (targetnames; Source compares names without regard to case). Every entity whose targetname equals one of them is a template entity.
*   At map load the engine removes the template entities from the world unless the template's `spawnflags` bit 1 ("don't remove template entities") is set. Copies appear only when the template is spawned.
*   An entity may be named by several templates; one is enough.
*   Entities that are parented to a template entity (a `parentname` equal to a templated name) are not drawn by the extractor already (RFC 18 4.2, RFC 33 3: a parented entity is not drawn).

## 4. Design
*   **Read the names first.** `extractMapEntities` (`bsp.ts`) reads the entity lump in one pass and decides at the closing brace of each entity. The decision for an entity depends on templates that may come **later** in the lump, so the entities are collected first (or the template names in a first pass over the text) and decided after. The set of templated names is built from every `point_template` whose `spawnflags` bit 1 is clear: the lower-cased values of the keys `template01` to `template16` (keys are lower-cased at parse, RFC 33 9a), trimmed, non-empty.
*   **One rule for everything the entity lump yields.** An entity whose lower-cased `targetname` is in the set is **not drawn and not placed**, whatever it is: a brush entity (fixture, movable part, decoration, water brush: it is not a fixture), a `prop_*` placed by the entity lump (`entityProps`: it is not placed), a spawn point (`info_player_*`: not a spawn), anything. This sits next to `hiddenAtStart` and the start-state rule of RFC 35: a part is dropped if it is hidden, starts open and cannot be placed, **or is templated**.
*   **Not hiding the template's own entity.** The `point_template` itself is a point entity without a model; it was never drawn.
*   **Counted.** The coverage record (RFC 32) gets `templated`: the number of entities left out for this reason, by class (top classes), and the number of `point_template` entities read. They only count; they do not change what else is drawn.
*   **Mesh version:** `MESH_VERSION` and `MESH_VERSION_GAME` each go up by one; the stored maps are rebuilt once.

## 5. The census
The coverage page's card "Where moving parts start" (RFC 35) gets a second table (or a second card): "Entities not in the world at round start": per map, the number of entities left out because a template names them, with the largest classes, summed over the maps with a record. After the deployment and the rebuild it shows how many of the maintainer's 28 maps have templates and how many entities they hide.

## 6. Tests (what must fail on a broken build)
*   Plain code: the set of templated names from a constructed entity lump (Hammer's spelling `Template01` ... `Template16`, mixed case, spaces, empty values, a template with `spawnflags 1` is ignored, a template with `spawnflags 2` counts); a name match is case-insensitive.
*   The extractor on a small constructed BSP: a `func_physbox` named `DiaBlock` named by a template is absent from `fixtureModels`, the movable group and the decoration group; the same entity with a template of `spawnflags 1`, or with no template, is drawn; a templated `prop_dynamic` is not placed (`entityProps`); a templated `info_player_start` is not a spawn; a template listed **after** the entity in the lump still hides it (order independence); a name named by two templates; an entity with no targetname is never hidden.
*   The record: `templated` counts by class; an old record without it loads; the census table's totals and ranking, no layout jump, contrast.
*   A map with no templates gives the same bytes as before (the pinned-hash test, apart from the version number the file carries).
*   Mutation checks: template keys case-sensitive, only `template01` read, `spawnflags` bit ignored, order dependence (decided at the closing brace), the rule applied to brush entities only, the count missing.

## 7. Check on the real maps (required before it is called done)
Build and render `ttt_minecraft_b7_summer` (the furnace block: the diamond cube and the gold block must be gone from in front of the furnace; list every `func_physbox`, prop and other entity the rule removes, with class, name and position, and look at the picture of each region where something disappears: nothing that a player sees at round start may vanish), and on the other maps already downloaded (`ttt_community_pool`, `ttt_67thway_rework_b1`, `ttt_mc_skyislands`) count the templates and the entities they name. Before and after pictures from the same cameras.

## 8. What cannot be verified here
*   The other maps: measured by the census after the deployment.
*   Entities that a template names by a name with a wildcard or a name that matches by prefix: Source does not use wildcards in `Template01`..`16` as far as I know; none was seen on the maps read.
*   That the engine removes a templated *brush* entity's model from the world too (it does for every entity named in a template; this is the documented behaviour of `point_template`), and that a physbox is not left as a "template" source in some other way: the first replay after the deployment is the check.
