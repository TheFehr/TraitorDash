# RFC 17: One Look for the Public Pages (and the Game's Window)

> **Status: stages 1 and 2 built (2026-10-22), not yet tried in the game.** The shell, the kit, and the public pages (home for visitors, round stats, one round, one player, maps, one map, the 3D view, the replay), merged with the pages of RFC 16. Stage 2 (the admin pages, with dark tables) is built too; stage 3 (removing Tailwind) is not started.

## 1. Abstract
The dashboard had two looks and two sets of pages for the same things: Tailwind pages for the website and, since RFC 16, hand-styled case-file pages for the game's window. The game's built-in browser is **Chrome 86** (2020), which cannot read the Tailwind stylesheet (it is built on cascade layers, `oklch()` and `color-mix()`, from Chrome 99 to 111), so the replay and the 3D view showed up unstyled and their scripts did not run at all. This RFC makes the case-file look the look of the public pages, with **one component per page** for the website and the window alike.

## 2. Decisions
*   Public pages first, admin pages later (stages 2 and 3), because the replay and the 3D view are what the game needs.
*   When the admin pages move, they get the case-file shell and fonts but **dark tables and forms** (dense, long sessions); the public pages stay paper on a dark desk.

## 3. Design (stage 1)
*   **One shell** (`components/CaseFile.tsx`). On the website it has a header with the account links (home, Servers and the admin mark for an admin, the SteamID64 for a user, Logout, or "Sign in with Steam"); `?embed=1` takes the header away. The one stylesheet is inline and hand-written for Chrome 86 (no `@layer`, no `oklch`, no `inset`, no `:where`). The fonts are served by the app.
*   **One kit** (`components/kit.tsx`): file cards, stamps, the result tag, win bars, numbers, the log table, tabs and pills, the "Signed in as" foot for the window. A page says what it shows; the look is decided in the kit and the stylesheet.
*   **One page per thing**, for the website and the window: `StatsPage` (Overview, Leaderboard, Rounds), `RoundPage`, `PlayerPage` (`components/StatsPages.tsx`); `MapsPage`, `MapFilePage`, `MapViewPage` (`components/MapPages.tsx`); `ReplayPage`; `HomePage`. What differs is `ctx` (`embed`, who is looking): no header and no admin controls in the window; an admin on the website also gets the tracks card, the ticks and delete buttons on the Rounds tab, the sizes and floor-plan pills on the maps, the geometry switch and the floor plans on a map's page, and pin and delete on the replay. The pages of RFC 16 (`GamePages.tsx`) and the Tailwind versions of these pages are gone.
*   **Routes.** Unchanged addresses, plus: `/servers/:id/rounds/:roundId` (one round) and `/servers/:id/maps/:map/rounds` (one map's rounds) are now public pages on the website too. The stats page is tabbed (`?view=leaders|rounds`); the admin actions redirect to the Rounds tab. A visitor with no session is offered the Steam login on the website; in the window nobody is sent to it (the replay and the 3D view go back to the round and map pages).
*   **Headers.** One content-security-policy for these pages: nothing but their own stylesheet, fonts and images. A page that has scripts (the replay, the 3D view, a confirmation) adds `script-src 'self'; connect-src 'self'` and images from `blob:`; never an inline script, never another site. `private` caching with an ETag (an admin's page is checked on every request), one rate limit per address shared with the role guide.
*   **Confirmation.** The pages have no inline script, so a form that asks first says so in `data-confirm` and loads `/public/confirm.js` (a few lines).
*   **The browser code.** `replay.ts` and `mapview.ts` build their lists with the kit's class names instead of Tailwind's. Bun writes three.js's class static blocks (`static { X.prototype.isY = true }`, Chrome 94), which stop a script from loading in Chrome 86; `scripts/oldbrowsers.ts` runs after the build, rewrites them as the static fields that do the same, and **fails the build** on anything else Chrome 86 cannot parse. `test/oldbrowsers.test.ts` builds the real bundles and checks them.
*   **Tests.** The tests that read the old markup read the new one (tabs instead of one long page, cards instead of table rows); the `data-*` hooks (`data-replay-link`, `data-tracks`, `data-delete-selected`, `data-3d`, ...) are kept.

## 3a. Trying it in Chrome 86
A container with the same browser version as the game's window runs the pages without the game: `docker run -d --network host --entrypoint /opt/google/chrome/google-chrome selenium/standalone-chrome:86.0 --headless --no-sandbox --remote-debugging-port=9333 --use-gl=swiftshader --enable-unsafe-swiftshader about:blank`, then drive it over the DevTools protocol (Playwright's `connectOverCDP`). It found `findLastIndex` (Chrome 97) stopping the replay, which the syntax check cannot see; `test/oldbrowsers.test.ts` now also searches our browser code for the usual newer methods. It is not the game's own build: the game may have WebGL off, which the pages now say instead of staying on "needs JavaScript".

## 4. Stage 2 (built): the admin pages
*   The same `Shell` with `admin`: the case-file header, fonts and colours, plus `components/AdminCss.ts` (dark panels `.pn`, tables `table.data`, form fields `.fld`, the on/off switch, buttons `.ab`, call-outs) and `/public/frontend.js` (htmx and Alpine, as before, still from our own bundle). The header is as wide as the page.
*   `components/AdminPages.tsx` puts each page in the shell (`AdminHomePage`, `ServersPage`, `ServerPage` and `RoleConfigPage` with the role sidebar); `AdminDashboard`, `ServerManager`, `ServerDashboard`, `Sidebar` and `RoleConfigForm` keep their jobs and their `x-`/`hx-`/`data-` hooks, with class names instead of Tailwind's. The server page uses the same `Sections` links as the public pages. The role colour is the tab of its tile. "Configure →" is always visible, not only on hover.
*   `Layout.tsx` is gone; the logo emoji and the tab icon live in `components/brand.ts`.
*   Phones: the role list folds behind a "Roles" bar; the servers table scrolls sideways inside its panel.

## 5. Stage 3 (not started)
*   Remove the Tailwind CLI, `src/style.css`, `public/style.css`, the class strings in `ui.ts` and the `build:css` step; the one stylesheet is the inline one.
